# MicroWallet — учебный аппаратный кошелёк на ESP32-S3

Прошивки, приложения и APK — в [релизах](https://github.com/delarun/MicroWallet/releases).

Монеты: **BTC**, **Pearl** (PRL), **TRON** (TRX, USDT-TRC20, TRC10), **BNB Chain** (BNB, USDT-BEP20),
**Ethereum** (ETH, USDT, USDC), **TON** (GRAM — бывший Toncoin, USDT) — из одной мнемоники (12/18/24 слова). В прошивке только ключи,
экраны и связь; каждая монета — приложение WebAssembly в песочнице, ставится и обновляется
отдельно (как у Ledger).

- ESP32-S3 SuperMini, экран SSD1306 128×64, одна кнопка, аккумулятор с зарядкой на плате;
- связь по USB и Bluetooth LE (свой шифрованный канал), приложения для Android, ПК и консоли;
- seed из аппаратного ГСЧ; обновление прошивки и приложений — только с подтверждением кнопкой;
- защищённая сборка: Secure Boot v2 + шифрование флеша и NVS.

> ⚠️ **По умолчанию сборка — testnet** (BTC testnet4, TRON Nile, BSC testnet, Pearl testnet2, TON testnet).
> В обычной сборке seed лежит во флеше открыто: у кого устройство, у того и монеты. Это учебный
> проект — на mainnet держи только мелкие суммы.

## Установка

| Файл из релиза | Как ставить |
|---|---|
| `microwallet-esp32s3-{testnet,mainnet}-full.bin` | первый раз: `esptool.py --chip esp32s3 write_flash 0x0 …-full.bin` |
| `…-{testnet,mainnet}-app.bin` | обновление: с телефона или `python host/wallet.py update …-app.bin` |
| `…-{testnet,mainnet}-secure-app.bin` | обновление платы с Secure Boot (подписано релизным ключом) |
| `microwallet-app-*.wasm`, `…-apps.bin` | приложения: по одному с телефона / `wallet.py app-install`, все разом — `write_flash 0x280000` |
| `microwallet-android.apk` | приложение для Android (дальше обновляется само) |

Seed и настройки при обновлении сохраняются. Разметка 4 МБ: nvs 0x9000, два слота прошивки
по 1.19 МБ (0x20000, 0x150000), приложения 1.5 МБ с 0x280000. Новая прошивка считается годной
после 30 с работы — упадёт раньше, загрузчик вернёт прежнюю.

## Железо

| ESP32-S3 SuperMini | |
|---|---|
| Экран SDA / SCL | GPIO8 / GPIO9 (I2C 100 кГц, адрес 0x3C) |
| Кнопка → GND | GPIO1 (будит из выключения); BOOT (GPIO0) тоже работает |
| Аккумулятор | BAT+/BAT− снизу; напряжение — делитель VBUS/2 на плате (GPIO3) |

Пины меняются в `idf.py menuconfig` → MicroWallet. Перемычку BOOST (ток заряда 300 мА) для
аккумуляторов меньше 500 мА·ч не трогай; светодиоды питания лучше выпаять.

**Питание от аккумулятора впритык**: BAT → диод → LDO с 1 мкФ на входе, в пик (запуск радио)
3.3 В проседает до ~2.9 В. Поэтому детектор просадки — на заводских 2.44 В, мощность BLE — 0 дБм,
ниже 3.55 В тяжёлые операции не начинаются, ниже 3.45 В устройство выключается. Лучшее лекарство —
конденсатор 100–470 мкФ между VBUS и GND. Причину сброса показывает `boot=` в `info`
(`brown@ble` — просадка при запуске Bluetooth).

**Сон.** Через минуту простоя гаснет экран (лёгкий сон, Bluetooth на связи), через две
устройство выключается (глубокий сон, будит кнопка). Пока подключён USB или телефон — не спит.
Настраивается в Settings → Sleep / Power off.

## На устройстве

Кнопка: **нажатие** — следующий экран, **удержание 0.75 с** — выбрать. Главный экран — строка
иконок приложений (как у Ledger Nano X), сверху сеть, Bluetooth, USB и заряд.

```
Bitcoin ─ Pearl ─ TRON ─ BNB Chain ─ Ethereum ─ TON ─ Settings
   └─ Receive ─ About ─ Remove ─ Back
Settings: Brightness ─ Sleep ─ Power off ─ Addresses ─ Turn off ─ Battery ─ Bluetooth ─
          Forget PCs ─ MicroWallet ─ Wipe ─ Back
```

Всё, что требует решения, идёт по шагам до **Accept** / **Reject**: подпись (сумма, получатель,
комиссия, «High fee!»), показ адреса, код сопряжения, восстановление seed, установка прошивки или
приложения (размер и SHA-256). Адреса и хеши — группами по 4 символа. При холодном старте экран
говорит, защищён ли seed: «Encrypted» или «Not encrypted». **Addresses** — сколько адресов для
получения (1/5/10/20).

![Экраны 128x64](docs/device-screens-64.png)

**Первый запуск:** «New wallet» → 12 слов по одному (запиши) → проверка двух слов. Готовую
фразу можно ввести с телефона или ПК («Восстановить из seed-фразы», `wallet.py restore`) —
устройство покажет первое и последнее слово; но телефон или ПК фразу видит.

## Приложения

**Android** (`android/`, Kotlin + Compose, по Bluetooth): обзор балансов (обновление жестом
вниз), получить (QR, проверка на устройстве), отправить (QR-сканер, проверка адреса, комиссия,
memo для TRON, комментарий для TON), устройство (прошивка с GitHub/ПК/файла с выбором версии, приложения и их порядок
на экране, PSBT, проверка Pearl Wallet). Само обновляется из релизов (сверка SHA-256). Есть демо.

**ПК** — `python host/app.py` (`--ble auto`, `--demo`), то же самое; зависимости —
`pip install -r host/requirements.txt`.

![Обзор](docs/app-overview.png)

**Консоль:**
```sh
python host/wallet.py info                     # --ble auto — по Bluetooth
python host/wallet.py update …-app.bin         # прошивка; app-install / apps / apps-order — приложения
python host/wallet.py btc receive | balance | send tb1q… 10000 --feerate 2 --dry-run
python host/wallet.py tron send T… 12.5                                   # USDT
python host/wallet.py tron send T… 3 --token trx --memo "invoice 42"      # TRC10: --token trc10:<ID>
python host/wallet.py bsc send 0x… 0.01 --token bnb
python host/wallet.py prl send prl1p… 12.5     # prl compat — совместимость с Pearl Wallet
python host/wallet.py ton send UQ… 1.5 --memo "hi"                         # USDT: --token usdt
python host/wallet.py btc descriptor           # watch-only для Sparrow/Electrum
python host/wallet.py btc psbt-sign tx.psbt -o signed.psbt [--broadcast]
```

**Bluetooth.** Первое подключение — один и тот же 6-значный код в приложении и на экране,
удерживай «Pair». Канал: X25519 → HKDF-SHA256 → ChaCha20-Poly1305, код выводится из обмена
ключами (подмена посередине видна), повтор или подмена кадра рвут сессию. До 4 сопряжений.

**PSBT.** Кошелёк ведёт Sparrow или Electrum (watch-only по дескриптору), подписывает устройство.
PSBT разбирает хост, но получателей, сдачу и суммы входов проверяет устройство. Только свои
P2WPKH-входы и SIGHASH_ALL; мультиподписи и подписи без провода нет.

**Pearl.** Адрес из `prl receive` годится для выплат пула или `pearld --miningaddr`. Pearl Wallet
выводит ключи нестандартно (btcd `DeriveNonStandard`, ошибка #172): примерно у 0.8 % фраз его
адреса другие. Проверка — `prl compat` или «Устройство → Pearl Wallet» (ответ одним битом, ключи
не раскрываются). Монетам на адресах устройства это не грозит.

**TON.** Кошелёк W5 (v5R1), ключи — как в TON-приложении Ledger: `m/44'/607'/0'/0'/i'/0'`
(testnet — `…/1'/…`). Ledger с той же фразой даст тот же ключ, но Ledger Live показывает
адрес контракта v4R2; адрес W5 виден в Tonkeeper, если подключить Ledger и выбрать версию W5.
Первая отправка разворачивает кошелёк (в сообщение добавляется StateInit). Данные — toncenter,
ключ можно задать в `TONCENTER_API_KEY`.

**TRON.** Сколько TRX сгорит (энергия, bandwidth, активация, memo), хост оценивает по ноде;
лимит по умолчанию — 40 TRX или оценка + 20 %. Для TronGrid можно задать `TRONGRID_API_KEY`.

## Что проверяет устройство

Приложение — модуль WebAssembly (движок WAMR) со своей памятью 64 КБ. Ключи, экран и кнопку оно
получает только через прошивку (`sdk/mw.h`):
- ключи — только по путям из манифеста приложения;
- подпись — только после «Accept» в этом же вызове;
- сбой модуля или вечный цикл (лимит 50 млн инструкций на вызов) останавливают модуль, не прошивку;
- перед запуском проверяется SHA-256 модуля; установка и удаление — с подтверждением.

| Монета | Путь | Что проверяется |
|---|---|---|
| BTC | `m/84'/1'/0'` (mainnet `84'/0'`) | получатели на экране; адрес сдачи выводит само; суммы входов — по предыдущим транзакциям целиком. До 64 входов и 16 выходов |
| PRL | `m/86'/1'/0'` (mainnet `86'/808276'/0'`) | BIP341 подписывает суммы всех входов; выводы P2TR и P2MR |
| TRON | `m/44'/195'/0'/0/i` | сам разбирает protobuf ноды: один контракт (TRX, TRC10, `transfer()` USDT), лишние поля — отказ; memo на экране; `fee_limit` — потолок, оценку хоста выше потолка отклоняет |
| BSC, ETH | `m/44'/60'/0'/0/i` | строгий RLP, legacy EIP-155 и EIP-1559; только перевод или `transfer()` токена из белого списка; nonce и сеть на экране |
| TON | `m/44'/607'/0'/0'/i'/0'` (testnet `…/1'/…`) | сам разбирает BoC сообщения W5: одно действие с режимом 3, без StateInit; тело — пусто, комментарий или перевод USDT на **свой** кошелёк USDT (адрес считает сам), сдача — себе; wallet_id своей сети |

Кроме secp256k1 прошивка умеет ed25519 (SLIP-10) и sr25519 (Substrate) — для будущих приложений.

## Сборка и тесты

```sh
./get_deps.sh                                    # lib/: trezor-crypto, WAMR, sr25519-donna
. ~/esp/esp-idf/export.sh                        # ESP-IDF 5.4
cd esp32 && idf.py build flash                   # testnet; mainnet: -D SDKCONFIG_DEFAULTS="sdkconfig.defaults;sdkconfig.mainnet"
sh apps/build.sh                                 # приложения (clang с wasm32)
tools/release.sh [v0.7.3]                        # всё для релиза в build/release/ (и публикация через gh)
```

Симулятор — то же ядро на ПК (`tools/sim/build.sh mwsim`), на нём тесты:
`test_apps` (песочница, EVM), `test_golden` (адреса и подписи против эталонов), `test_utxo`,
`test_psbt` (против embit), `test_tron`, `test_ton` (против @ton/ton), `test_btcd`, `test_curves`, `test_store`
(`python3 tools/sim/<тест>.py mwsim`). Android: `MW_SIM=… ./gradlew testDebugUnitTest` —
Kotlin-кошелёк собирает те же транзакции байт в байт, что `host/wallet.py`.

Приложение — папка `apps/<id>/` с `<id>.c` (`mw_main`) и `manifest` (`id`, `name`, `version`,
`icon`, `path`). Протокол — строки по USB или внутри BLE-канала; команды описаны в начале
`src/app.c`, `src/apps.h` и файлов приложений.

### Защищённая сборка

`sdkconfig.secure`: Secure Boot v2 (RSA-3072), шифрование флеша и NVS. **Первая загрузка
необратимо прожигает eFuse**: дальше запускается только подписанная прошивка, флеш читается
только как шифротекст, JTAG выключен.

- Ключей три (личный, релизный, резервный); загрузчик прожигает хеши всех ключей, которыми
  подписан, а пустые слоты отзывает — набор выбирается один раз. Потеряешь все три — плату не
  обновить. `*.pem` в репозиторий не попадают.
- **Подвох ESP-IDF:** ключу из слота k загрузчик верит, только если у образа есть блок подписи k.
  Релизный ключ (слот 1) — две подписи, резервный — три; иначе обновление запишется, а плата
  загрузит старую прошивку. `tools/release.sh` подписывает правильно.
- Режим Development: по USB можно записать подписанный образ
  (`esptool.py write_flash --encrypt 0x20000 …-secure-app.bin`). Release — отдельно через espefuse.
- У защищённой сборки своя таблица разделов (с 0xD000), обновляется только `…-secure-app.bin`.

## Известные слабые места

1. Seed в открытом виде в обычной сборке; защищённая — пока в режиме Development.
2. Seed, введённый на телефоне или ПК, видит это устройство; ввода на самом устройстве нет.
3. TRON: реальную стоимость устройство знает со слов хоста (проверяет только потолок); имя и
   точность TRC10 не проверить.
4. EVM: nonce и цену газа сообщает хост; BSC с телефона уходит legacy-транзакцией. TON: seqno и
   срок сообщения тоже от хоста (устройство их не показывает: ошибка в них не тратит деньги).
5. Pearl: только key-path Taproot, своих P2MR/XMSS-ключей нет.
6. Прошивка по Bluetooth идёт кусками по одному (~70 с): с конвейером вставала на 1 %, причина не найдена.
